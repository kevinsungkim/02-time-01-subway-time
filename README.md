# subway_time | TIME PART: 시간대 기준 만들기

## 프로젝트 개요

`02-time-01-subway-time`은 서울열린데이터광장의 「서울시 지하철 호선별 역별 시간대별 승하차 인원 정보」를 상권 이동 분석에 활용할 수 있도록 전처리하는 TIME PART 프로젝트입니다.

원본에서 시간별로 가로 배치된 승차·하차 컬럼을 `아침출근`·`낮`·`저녁퇴근`·`밤`의 네 개 시간대로 재구성하고, 분석에 필요한 날짜·시간 및 주요 컬럼 구조를 정리해 `subway_time` 분석용 데이터셋을 만듭니다.

포트폴리오의 DATE/TIME 전처리는 다음 흐름으로 구성됩니다.

* DATE PART: 날짜와 공휴일 기준을 정리해 일별 분석 기준 생성
* TIME PART: 시간대별 승하차량을 분석 목적에 맞는 시간 구간으로 재구성

이 저장소는 DATE PART에서 만든 날짜 축에 이어, 하루 중 이동이 언제 발생하는지 살펴보기 위한 시간 축을 만드는 단계입니다.

## 전처리 목적

시간별 승하차 인원을 네 개의 분석 구간으로 집계하면 출근 이동, 주간 활동, 퇴근 후 소비, 야간 상권 이동을 월·호선·역 단위로 비교할 수 있습니다.

가로로 길게 구성된 원본 데이터를 `time_period` 기준의 세로형 분석 데이터로 재구성해, 필요한 시간대를 필터링하거나 Tableau에서 시간대별 이동 흐름을 시각화할 수 있도록 합니다.

또한 원본의 사용월·역명·노선명을 분석용 기준에 맞게 정리하고, `24:00:00`처럼 분석 도구에서 시간 파싱 오류가 발생할 수 있는 값은 안정적으로 사용할 수 있는 형태로 보정합니다.

## 입력 데이터

### `raw_subway_time_sample.csv`

홍대입구역을 기준으로 구성한 포트폴리오용 미니 샘플입니다. 전체 원본 데이터나 실제 상권 이동 분석에 사용한 전체 역 데이터는 저장소에 포함하지 않고, 실제 데이터베이스에서 추출한 428행의 Raw Sample을 사용합니다.

샘플은 전체 데이터 규모를 재현하기 위한 더미 데이터가 아니라, 실제 컬럼 구조와 값을 이용해 전처리 코드의 입력·출력 관계를 보여주기 위한 자료입니다.

`raw_subway_time_sample.csv`는 `cp949` 인코딩의 wide format CSV이며, 한 행은 특정 `사용월`·`호선명`·`지하철역` 조합의 시간별 승차 및 하차 인원을 나타냅니다.

실제 샘플은 총 52개 컬럼으로 구성됩니다.

* 기본 정보: `사용월`, `호선명`, `지하철역`
* 시간별 승하차: `04시-05시`부터 익일 `03시-04시`까지
* 적재 정보: `작업일자`

```text
사용월
호선명
지하철역
04시-05시 승차인원
04시-05시 하차인원
...
23시-24시 승차인원
23시-24시 하차인원
00시-01시 승차인원
...
03시-04시 하차인원
작업일자
```

전처리에서는 `사용월`, `호선명`, `지하철역`과 분석 대상 시간 컬럼을 사용합니다. 데이터 적재 시점을 나타내는 `작업일자`는 최종 분석 데이터셋에 포함하지 않습니다.

실제 Raw Sample의 첫 행 일부는 다음과 같습니다.

| 사용월    | 호선명 | 지하철역 | 06시-07시 승차인원 | 06시-07시 하차인원 | 07시-08시 승차인원 | 07시-08시 하차인원 |
| ------ | --- | ---- | -----------: | -----------: | -----------: | -----------: |
| 201501 | 2호선 | 홍대입구 |       43,456 |       19,002 |       86,687 |       38,225 |

## 기본 컬럼과 명칭 정리

Raw Data의 주요 컬럼은 분석에 필요한 형태로 정리합니다.

| Raw Data | Processed Data                                        |
| -------- | ----------------------------------------------------- |
| `사용월`    | `month_start_date`, `month_end_date`, `year`, `month` |
| `호선명`    | `line_name`                                           |
| `지하철역`   | `station_name`                                        |

Raw Data의 `사용월`은 `201501`과 같은 `YYYYMM` 형식으로 제공됩니다. 이를 기준으로 해당 월의 시작일과 종료일을 만들고, 연도와 월을 각각 `year`, `month`로 분리합니다. `사용월` 자체는 별도의 분석용 컬럼으로 유지하지 않습니다.

Raw Data의 `지하철역` 값에는 `역` 표기가 없어, 상권명·지역명과 구분하고 역 단위 데이터임을 명확히 하기 위해 이름 끝에 `역`을 붙입니다.

원본의 노선명은 현재 노선도에서 사용하는 명칭에 맞춰 정리합니다.

| Raw Data   | Processed Data |
| ---------- | -------------- |
| `2호선`      | `2호선`          |
| `경의선`      | `경의중앙선`        |
| `공항철도 1호선` | `공항철도`         |

## 전처리 흐름

```text
시간대별 지하철 Raw Data
                 ↓
사용월 및 기본 컬럼 확인
                 ↓
month_start_date, month_end_date, year, month 생성
                 ↓
역명·노선명을 분석용 기준으로 정리
                 ↓
시간별 승하차 컬럼을 네 개 구간으로 집계
                 ↓
time_period, time_start, time_end 생성
                 ↓
승차·하차·총 승하차 인원 계산
                 ↓
subway_time 기본 데이터셋
                 ↓
역별 분석 메타데이터 결합
                 ↓
상권 이동 분석용 subway_time
```

## TIME PART 기준

시간별 승하차량은 상권 이동 분석 목적에 맞춰 다음 네 개 구간으로 나눕니다.

| time_period | 시간 범위                   | 집계 대상 Raw Data 컬럼     | 해석             |
| ----------- | ----------------------- | --------------------- | -------------- |
| `아침출근`      | `06:00:00` ~ `09:00:00` | `06시-07시` ~ `08시-09시` | 출근·등교 중심 이동    |
| `낮`         | `09:00:00` ~ `18:00:00` | `09시-10시` ~ `17시-18시` | 업무·관광·일상 소비 이동 |
| `저녁퇴근`      | `18:00:00` ~ `21:00:00` | `18시-19시` ~ `20시-21시` | 퇴근 후 소비·약속 이동  |
| `밤`         | `21:00:00` ~ `23:59:59` | `21시-22시` ~ `23시-24시` | 야간 상권·귀가 이동    |

## `00시~06시` 제외 기준

`subway_daily`와 `subway_time`의 월간 합계를 비교했을 때 `00시~06시` 이용객은 전체의 3% 미만 수준입니다. 또한 이 시간대는 상권 이동의 큰 흐름보다 심야 귀가나 새벽 이동처럼 특수성이 강합니다.

따라서 Raw Sample에는 `00시-01시`부터 `05시-06시`까지의 컬럼이 존재하지만, 네 개 분석 시간대의 집계에는 사용하지 않습니다.

월간 합계의 정합성은 별도의 검증 SQL에서 확인하고, 이 저장소에서는 상권 이동 분석에 사용할 시간대 기준을 만드는 과정에 집중합니다.

## `24:00:00 → 23:59:59` 예외 처리

Raw Data의 `23시-24시` 승하차량은 `밤` 구간에 포함합니다.

다만 `24:00:00`은 Python, SQL, Tableau 등에서 일반적인 시간값으로 처리하기 어려울 수 있으므로 `time_end`는 `23:59:59`로 저장합니다.

이를 통해 날짜가 넘어가는 시점의 모호함을 줄이고 여러 분석 도구에서 일관되게 사용할 수 있는 시간 기준을 만듭니다.

Raw Sample 428행마다 네 개의 `time_period` 행이 생성되므로 Processed Sample은 총 1,712행입니다.

## 실제 상권 이동 분석용 `subway_time`

GitHub의 Processed Sample은 TIME PART의 전처리 구조를 보여주기 위한 미니 샘플이며, 실제 상권 이동 분석에서는 동일한 시간대 기준을 전체 분석 대상 데이터에 적용한 뒤 역별 분석 메타데이터를 추가로 결합했습니다.

추가한 메타데이터는 다음과 같습니다.

| column           | description                        |
| ---------------- | ---------------------------------- |
| `station_id`     | 역 식별 ID                            |
| `nearby_station` | 상권 분석에 사용하는 인접 역 기준                |
| `district`       | `건대`, `성수`, `홍대`, `신촌` 등 분석용 지역 그룹 |
| `axis`           | `건대-성수축`, `신촌-홍대축` 등 상권 이동 분석 축    |

실제 상권 이동 분석에 사용한 `subway_time` 데이터셋은 다음 16개 컬럼으로 구성됩니다.

```text
station_id
line_name
station_name
nearby_station
district
axis
month_start_date
month_end_date
year
month
time_period
time_start
time_end
in_passengers
out_passengers
total_passengers
```

최종 분석 데이터는 **16개 컬럼, 8,284행**으로 구성됩니다.

각 월·노선·역 단위 데이터가 `아침출근`·`낮`·`저녁퇴근`·`밤`의 네 개 `time_period` 행으로 재구성되며, 여기에 역별 메타데이터를 결합해 상권별·분석축별 시간대 이동 패턴을 비교할 수 있도록 만들었습니다.

역별 메타데이터는 시간대별 승하차량 자체를 만드는 과정에서 생성하는 값이 아니라, 여러 역을 동일한 상권과 분석 축으로 묶어 비교하기 위해 이후 분석 단계에서 결합한 정보입니다.

## 실행 방법

Python 3.10 이상 환경을 권장합니다.

저장소 루트에서 필요한 패키지를 설치한 뒤 전처리 코드를 실행합니다.

```bash
pip install -r requirements.txt
python src/preprocess_subway_time.py
```

코드는 `data/sample/raw_subway_time_sample.csv`를 입력으로 사용합니다. 실행 결과는 UTF-8 with BOM(`utf-8-sig`) CSV로 다음 경로에 저장됩니다.

```text
data/sample/processed_subway_time_sample.csv
```

실행 과정에서는 다음 항목을 함께 검증합니다.

* 필수 컬럼이 존재하는지
* 승하차 인원이 숫자형 값으로 처리되는지
* 최종 컬럼 순서가 올바른지
* `time_period`가 네 개 기준으로 생성되는지
* `밤` 구간의 종료 시각이 `23:59:59`인지
* 승차·하차 인원과 총 승하차 인원의 합계가 일치하는지

## 포트폴리오 관점의 의미

이 프로젝트는 시간별 컬럼을 단순히 합산하는 것이 아니라, 상권 이동을 설명할 수 있는 시간 기준을 설계하는 과정을 보여줍니다.

DATE PART에서 날짜와 공휴일 기준을 정리하고 TIME PART에서 하루의 이동을 네 개 구간으로 재구성함으로써, 상권 이동 분석에 필요한 DATE/TIME 축을 단계적으로 완성합니다.

또한 사용월·역명·노선명 정리, 시간 파싱 예외 처리, 분석 대상 시간대 설정을 거쳐 기본 `subway_time`을 만들고, 이후 역별 메타데이터를 결합해 실제 상권 이동 분석에 사용한 **16개 컬럼·8,284행의 데이터셋**으로 확장했습니다.
