# 서울시 지하철 시간대별 승하차 데이터 전처리

## 1. 프로젝트 개요

`02-time-01-subway-time`은 서울열린데이터광장의 「서울시 지하철 호선별 역별 시간대별 승하차 인원 정보」를 상권 이동 분석에 활용할 수 있도록 전처리하는 TIME PART 프로젝트입니다.

원본에서 시간별로 가로 배치된 승차·하차 컬럼을 `아침출근`·`낮`·`저녁퇴근`·`밤` 기준으로 재구성하고, 시간 파싱 오류가 발생할 수 있는 `24:00:00` 대신 `23:59:59`를 사용해 `subway_time` 분석용 데이터셋을 만듭니다.

포트폴리오의 DATE/TIME 전처리는 다음 흐름으로 구성됩니다.

- DATE PART: 날짜와 공휴일 기준을 정리해 일별 분석 기준 생성
- TIME PART: 시간대별 승하차량을 분석 목적에 맞는 시간 구간으로 재구성

이 저장소는 DATE PART에서 만든 날짜 축에 이어, 하루 중 이동이 언제 발생하는지 살펴보기 위한 시간 축을 만드는 단계입니다.

## 2. `subway_time` 데이터셋의 역할

시간별 승하차 인원을 네 개의 분석 구간으로 집계하면 출근 이동, 주간 활동, 퇴근 후 소비, 야간 상권 이동을 월·호선·역 단위로 비교할 수 있습니다.

가로로 긴 원본 데이터를 세로형 분석 데이터로 바꾸기 때문에 `time_period`를 기준으로 필터링하거나 Tableau에서 시간대별 이동 흐름을 시각화하기에도 적합합니다.

## 3. 포트폴리오용 샘플 데이터

이 저장소에는 전체 원본 데이터 대신 홍대입구역 관련 일부 데이터만 담은 미니 샘플을 올립니다. 전체 데이터는 파일 크기가 크고 포트폴리오의 핵심인 전처리 로직을 확인하는 데 필요하지 않기 때문입니다.

- `raw_subway_time_sample.csv`: 실제 데이터베이스에서 추출한 428행의 Raw Sample
- `processed_subway_time_sample.csv`: Raw Sample을 네 개 시간대로 전처리한 1,712행의 결과

샘플은 전체 데이터의 규모를 재현하기 위한 더미 데이터가 아니라, 실제 컬럼 구조와 값을 이용해 코드의 입력·출력 관계를 보여주기 위한 자료입니다.

## 4. 원본 Raw Data 구조

`raw_subway_time_sample.csv`는 `cp949` 인코딩의 wide format CSV입니다. 한 행은 특정 `사용월`·`호선명`·`지하철역` 조합의 시간별 승차 및 하차 인원을 나타냅니다.

실제 샘플은 총 52개 컬럼으로 구성됩니다.

- 기본 정보: `사용월`, `호선명`, `지하철역`
- 시간별 승하차: `04시-05시`부터 `23시-24시`, `00시-01시`부터 `03시-04시`
- 적재 정보: `작업일자`

```text
사용월
호선명
지하철역
04시-05시 승차인원
04시-05시 하차인원
...
23시-24시 승차인원
23시-24시 하차인원
00시-01시 승차인원
...
03시-04시 하차인원
작업일자
```

전처리에서는 `사용월`, `호선명`, `지하철역`과 분석 대상 시간 컬럼을 사용합니다. 데이터 적재 시점을 나타내는 `작업일자`는 최종 분석 데이터셋에 포함하지 않습니다.

실제 Raw Sample의 첫 행 일부는 다음과 같습니다.

| 사용월 | 호선명 | 지하철역 | 06시-07시 승차인원 | 06시-07시 하차인원 | 07시-08시 승차인원 | 07시-08시 하차인원 |
|---|---|---|---:|---:|---:|---:|
| 201501 | 2호선 | 홍대입구 | 43,456 | 19,002 | 86,687 | 38,225 |

## 5. 기본 컬럼과 명칭 정리

원본 컬럼명은 분석용 영문 컬럼명으로 변경합니다.

| Raw Data | 분석용 컬럼 |
|---|---|
| `사용월` | `use_month` |
| `호선명` | `line_name` |
| `지하철역` | `station_name` |

실제 샘플의 데이터베이스 표기와 최종 분석용 표기를 맞추기 위해 다음 명칭도 정리합니다.

| Raw Data 표기 | 분석용 표기 |
|---|---|
| `경의선` | `경의중앙선` |
| `공항철도 1호선` | `공항철도` |
| `홍대입구` | `홍대입구역` |

역명은 끝에 `역`이 없는 경우에만 접미사를 추가합니다.

## 6. 시간대 구분 기준

| time_period | 시간 범위 | 집계 대상 Raw Data 컬럼 | 해석 |
|---|---|---|---|
| `아침출근` | `06:00:00` ~ `09:00:00` | `06시-07시` ~ `08시-09시` | 출근·등교 중심 이동 |
| `낮` | `09:00:00` ~ `18:00:00` | `09시-10시` ~ `17시-18시` | 업무·관광·일상 소비 이동 |
| `저녁퇴근` | `18:00:00` ~ `21:00:00` | `18시-19시` ~ `20시-21시` | 퇴근 후 소비·약속 이동 |
| `밤` | `21:00:00` ~ `23:59:59` | `21시-22시` ~ `23시-24시` | 야간 상권·귀가 이동 |

## 7. `00시~06시`를 제외한 이유

`subway_daily`와 `subway_time`의 월간 합계를 비교했을 때 `00시~06시` 이용객은 전체의 3% 미만 수준입니다. 또한 이 구간은 상권 이동의 큰 흐름보다 심야 귀가나 새벽 이동처럼 특수성이 강합니다.

따라서 Raw Sample에는 `00시-01시`부터 `05시-06시`까지의 컬럼이 존재하지만, 네 개 분석 시간대의 집계에는 사용하지 않습니다. 월간 합계 정합성은 별도의 검증 SQL에서 확인하고, 이 프로젝트에서는 시간대 기준을 만드는 과정에 집중합니다.

## 8. `24:00:00 → 23:59:59` 예외 처리

`23시-24시` 승하차량은 `밤` 구간에 포함합니다. 다만 `24:00:00`은 Python, SQL, Tableau에서 정상적인 시간값으로 파싱되지 않을 수 있으므로 `time_end`는 `23:59:59`로 저장합니다.

이를 통해 날짜가 넘어가는 시점의 모호함을 줄이고 분석 도구 간에 안정적으로 사용할 수 있는 시간 기준을 만듭니다.

## 9. 최종 `subway_time` 데이터셋 구조

`processed_subway_time_sample.csv`는 12개 컬럼으로 구성됩니다.

| column | description |
|---|---|
| `month_start_date` | 해당 월의 시작일 |
| `month_end_date` | 해당 월의 종료일 |
| `year` | 연도 |
| `month` | 월 |
| `line_name` | 표준화한 호선명 |
| `station_name` | `역` 접미사를 정리한 지하철역명 |
| `time_period` | `아침출근`, `낮`, `저녁퇴근`, `밤` |
| `time_start` | 시간대 시작 시각 |
| `time_end` | 시간대 종료 시각 |
| `in_passengers` | 해당 구간의 승차 인원 합계 |
| `out_passengers` | 해당 구간의 하차 인원 합계 |
| `total_passengers` | 승차 인원과 하차 인원의 합계 |

실제 Processed Sample의 첫 행은 다음과 같습니다.

| month_start_date | month_end_date | year | month | line_name | station_name | time_period | time_start | time_end | in_passengers | out_passengers | total_passengers |
|---|---|---:|---:|---|---|---|---|---|---:|---:|---:|
| 2015-01-01 | 2015-01-31 | 2015 | 1 | 2호선 | 홍대입구역 | 아침출근 | 06:00:00 | 09:00:00 | 234,421 | 192,374 | 426,795 |

Raw Sample 428행마다 네 개 `time_period` 행이 생성되므로 최종 결과는 1,712행입니다.

## 10. Python 코드 실행 방법

저장소 루트에서 다음 명령을 실행합니다.

```bash
pip install -r requirements.txt
python src/preprocess_subway_time.py
```

코드는 실제 샘플 파일인 `data/sample/raw_subway_time_sample.csv`를 입력으로 사용합니다. 실행 결과는 UTF-8 BOM을 포함하는 `utf-8-sig` 인코딩으로 다음 경로에 저장됩니다.

```text
data/sample/processed_subway_time_sample.csv
```

실행 과정에서 필수 컬럼, 숫자형 값, 최종 컬럼 순서, `time_period`, `밤` 종료 시각, 승하차 합계의 정합성을 검증합니다.

## 11. 결과 파일

```text
data/sample/
├── raw_subway_time_sample.csv
└── processed_subway_time_sample.csv
```

- Raw Sample: 실제 데이터베이스 구조를 유지한 입력 파일
- Processed Sample: Python 코드로 재생성할 수 있는 분석용 결과 파일

## 12. 포트폴리오 관점의 의미

이 프로젝트는 시간별 컬럼을 단순히 합산하는 것이 아니라, 상권 이동을 설명할 수 있는 시간 기준을 설계하는 과정을 보여줍니다.

DATE PART에서 날짜와 공휴일 기준을 정리하고 TIME PART에서 하루의 이동을 네 개 구간으로 재구성함으로써, 분석에 필요한 DATE/TIME 축을 단계적으로 완성합니다. 동시에 명칭 표준화, 시간 파싱 예외 처리, 제외 구간 설정과 같은 실무적인 데이터 품질 문제도 함께 다룹니다.
